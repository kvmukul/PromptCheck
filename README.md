# promptcheck

**Unit tests and regression checks for LLM prompts. Zero dependencies.**

Changing a prompt, swapping a model, or bumping a temperature can quietly break behaviour you
relied on. `promptcheck` lets you describe what "good" looks like in a small TOML file, runs it
against any model, and tells you in CI exactly what regressed.

**Easier Explanation: It lets you write tests for AI prompts in a simple file, runs them against a model, and tells you if a change broke something that used to work.**

```
$ promptcheck run examples/failing_demo.toml

promptcheck · failing demo  [mock/mock]

 ✗ answer is too chatty  (1 run, 1ms)
     ✗ max_words: 20 words > 5
 ✗ model refuses a benign request  (1 run, 1ms)
     ✗ not_refusal: looks like a refusal ("i can't")
     ✗ contains: expected output to contain 'flour'
 ✓ this one is fine  (1 run, 1ms)

Result: 1/3 passed, 2 failed  in 0.00s
```

## Why this exists

- **Prompts are code, so they need tests.** A diff in a prompt file should fail a build the way a diff in a function does.
- **Regression-first.** Save a known-good run as a baseline; later runs fail only on tests that *used to pass*, so a team can adopt it on a messy prompt library without fixing everything first.
- **Handles non-determinism.** Run a test N times and require a pass rate (`runs = 10`, `min_pass_rate = 0.9`) instead of pretending outputs are deterministic.
- **Zero dependencies.** Pure standard library (Python 3.11+): providers use `urllib`, suites are TOML (`tomllib`), reports are generated by hand. It installs anywhere and has nothing to audit.

## Quick start

```bash
pip install -e .            # or run directly: PYTHONPATH=src python -m promptcheck ...
promptcheck init            # writes a starter promptcheck.toml
promptcheck run promptcheck.toml
promptcheck run examples/support_bot.toml --html report.html
```

The default provider is `mock`, which runs fully offline, so the examples work without an API key.

## Writing a suite

```toml
[suite]
name = "support bot"
provider = "anthropic"            # mock | anthropic | openai (any OpenAI-compatible API)
model = "claude-sonnet-5-5"
system = "You are a concise support assistant for {{product}}."

[suite.vars]
product = "Acme CRM"

[[defaults.assert]]               # applied to every test
type = "not_refusal"

[[tests]]
name = "extracts ticket as JSON"
prompt = "Return ONLY JSON with keys title and priority (1-5) for: '{{ticket}}'"
vars = { ticket = "Login page crashes on Safari, urgent" }
runs = 5                          # sample the model 5 times...
min_pass_rate = 0.8               # ...and require 80% of runs to pass
tags = ["structured"]

  [[tests.assert]]
  type = "json_schema"
  schema = { type = "object", required = ["title", "priority"], properties = { priority = { type = "integer", minimum = 1, maximum = 5 } } }
```

Prompts support `{{variables}}` (suite-level, overridable per test) and `prompt_file = "prompts/x.txt"`.
`mock_output` is used only by the mock provider, so you can develop a suite offline and then switch the
provider to a real model.

### Assertions

Run `promptcheck assertions` for the live list.

| Type | Checks |
| --- | --- |
| `contains`, `not_contains` | substring (optional `ignore_case`) |
| `contains_all`, `contains_any` | every / at least one of `values` |
| `equals`, `one_of`, `starts_with` | exact-ish matches |
| `regex` | `pattern`, optional `flags = "ims"` |
| `not_refusal` | reply doesn't read as an apology or refusal |
| `max_chars`, `max_words`, `min_words` | length limits |
| `latency_ms` | response time budget (`max`) |
| `json_valid`, `json_schema` | parseable JSON, tolerant of ```` ```json ```` fences; validated against a JSON-Schema subset |
| `similarity` | fuzzy match to a `reference`, with a `threshold` |
| `llm_judge` | a grader model checks a plain-English `rubric` (PASS/FAIL) |

Adding your own is one decorated function in `assertions.py`:

```python
@register("ends_with", "Output ends with `value`.", required=("value",))
def _ends_with(ctx, p):
    ok = ctx.output.rstrip().endswith(p["value"])
    return ok, "ends correctly" if ok else f"does not end with {p['value']!r}"
```

## Catching regressions in CI

```bash
# on main, with the prompts you trust:
promptcheck run suite.toml --save-baseline baseline.json

# on every pull request:
promptcheck run suite.toml --baseline baseline.json --junit junit.xml --html report.html
```

```
Baseline comparison
  ▼ regression: extracts ticket as JSON
  ▲ fixed: classifies sentiment
  + new: handles empty input
```

The command exits `1` if any test regressed (or if the pass rate drops below `--fail-under`), `2` on
config errors, `0` otherwise. Reports: terminal, `--html` (self-contained, dark-mode aware, failures first),
`--json`, and `--junit` for CI dashboards.

## Real providers

| Provider | Needs | Notes |
| --- | --- | --- |
| `anthropic` | `ANTHROPIC_API_KEY` | Messages API |
| `openai` | `OPENAI_API_KEY` | Also works with Ollama, vLLM, etc.: set `[suite.options] base_url = "http://localhost:11434/v1/chat/completions"`. Newer OpenAI models may need `token_param = "max_completion_tokens"`. |
| `mock` | nothing | Offline; the `llm_judge` always passes here, so never trust it for grading. |

Requests retry on 429/5xx with exponential backoff. Responses are cached on disk
(`.promptcheck_cache/`), keyed by provider, model, prompt, system, and sampling settings, so re-running
an unchanged suite costs nothing. Use `--no-cache` to force fresh calls. A separate judge model is set
with `[suite.judge]`.

## CLI reference

```
promptcheck run SUITE [-k NAME] [--tag TAG] [-w N] [-v] [--no-cache]
                      [--provider P] [--model M]
                      [--html F] [--json F] [--junit F]
                      [--baseline F] [--save-baseline F] [--fail-under RATE]
promptcheck init [PATH]
promptcheck assertions
```

## Project layout

```
src/promptcheck/
  config.py       TOML → validated Suite/Case dataclasses, templating
  assertions.py   assertion registry (add checks with a decorator)
  providers.py    mock / Anthropic / OpenAI-compatible, stdlib HTTP with retries
  runner.py       thread-pooled execution, multi-run pass rates, caching
  baseline.py     snapshot + diff for regression detection
  report.py       terminal, HTML, JSON, JUnit
  cli.py          argparse front end
tests/            56 unittest cases (stdlib only)
examples/         runnable offline suites
```
